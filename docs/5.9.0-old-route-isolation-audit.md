# 5.9.0 旧路线隔离清点审计

日期：2026-08-03

目标：只做隔离审计，不删除文件，不改业务逻辑。范围覆盖 5.9.8 / 5.9.9 / waders / `customer_label_v2_*` / `review_signal_*` 相关代码、测试、脚本、文档、fixture 和本地 artifact。

## 结论

旧路线没有完全退出主线。

- `customer_label_v2_*` 前台替换默认关闭；active route 会 import `customer_label_v2_frontstage.py` 和 `customer_label_v2_maturity.py`，但默认不会 import 或执行 `customer_label_v2_shadow.py`。
- `review_signal_*` 前台替换默认关闭；但 `review_signal_frontstage.py` 会在 active route import 时顶层加载 `review_signal_shadow.py` 的常量和 safety helper。它不会默认改用户结果，但不满足“active route 完全不加载 review-signal shadow 文件”的理想状态。
- waders 旧规则仍在主线：`workers/jobs.py` 写入分析结果时会调用 `specific_issue.enrich_aspects_json()`，该函数默认追加 waders 内容规则；结果页、导出和前端也会继续消费这些 occurrence 和 waders 防错规则。

因此：5.9.1 可以先进入“输出契约/样例设计”，但不能宣称 5.9.0 完全绿灯。进入 5.9.1 前需要 Erika 确认一个产品风险：waders 规则是短期保留为当前前台安全补丁，还是立即从主线抽出为 category-specific 隔离模块。

## 基本验证记录

已执行 import 检查：

```text
python3 -c "import backend_api.app.routes.analysis; import backend_api.app.routes.export; import review_analyzer.exporter; ..."
```

结果：

- `CUSTOMER_LABEL_V2_FRONTSTAGE_*` 默认全关；`allow_runtime_shadow=False`。
- `REVIEW_SIGNAL_FRONTSTAGE_*` 默认全关；`runtime_shadow_generation_allowed=False`。
- active analysis/export import 未加载 `backend_api.app.services.customer_label_v2_shadow`。
- active analysis/export import 会加载 `backend_api.app.services.review_signal_shadow`，原因是 `review_signal_frontstage.py` 顶层 import shadow 常量/helper。

已执行 worker import 检查：

```text
python3 -c "import workers.jobs; ..."
```

结果：

- `workers.jobs` import 未加载 `customer_label_v2_shadow` 或 `review_signal_shadow`。
- `workers.jobs` 会加载 `specific_issue.py`，而 `specific_issue.enrich_aspects_json()` 默认追加 waders 内容规则。

备注：命令输出里出现 Arrow `sysctlbyname` permission warning，是本地 sandbox 读取 CPU 信息失败导致，不影响 Python import 结果。

## 是否可以进入 5.9.1

结论：可以进入 5.9.1 的“输出契约设计”和 3-5 条样例准备，但不要把 5.9.0 标记为完全完成。

进入 5.9.1 的边界条件：

- 新 5.9.1 文件使用新命名，不依赖 `customer_label_v2_*` 或 `review_signal_*` 作为主入口。
- 先写 fragment-level contract，不改 active upload / results / export / frontend 行为。
- waders 旧规则短期视为“当前前台安全补丁”，不是新 5.9 的质量依据。
- 5.9.3 前必须决定：waders 规则抽出、收编为 category-specific evidence examples，还是在新链路替代后删除。

人工闸门给 Erika 的检查重点：

- 旧实验前台替换默认关闭。
- 旧 shadow 不会在 worker 默认执行。
- waders 规则仍会默认影响 waders 结果，这是本次审计发现的主要主线风险。
- 后续删除要等新 5.9 tests 和 active import 检查稳定后小批量做。
