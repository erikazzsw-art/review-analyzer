## 每个数字怎么算的（给 Erika 看）

### 错标率 16.1%

**算法**：逐条对比。系统输出的每个 label key 去 gold 列表里找，找不到就算 FP。FP 总数 / 系统输出总数 = 14/87 = 16.1%。

**14 个 FP**：系统标了但人工没标的 label。例如 review #371 系统标了 `useful_accessories`（gold 没标），review #372 系统标了 `runs_too_large`（gold 只有 `fits_as_expected`）。

### 漏标率 20.6%

**算法**：gold 里的每个 label key 去系统输出列表里找，找不到就算 FN。FN 总数 / gold 总数 = 19/92 = 20.6%。

**19 个 FN**：人工标了但系统没标出来的。主要原因是 LLM 输出缺失 waders 专属 aspect key（waterproof=0, seam_integrity=0 等）。

### 极性反标数 3（修正定义）

**修正定义**：差评(≤2)出 highlight 或好评(≥4)出 issue，**且 gold 没标同类型 label** 才算反标。

**3 条明细**：

| review_no | rating | 类型 | 反标label | gold 也标了（不算反标） | 内容片段 |
|-----------|--------|------|-----------|----------------------|----------|
| #366 | 5 | 好评出issue | runs_too_small | size_fit_problem（gold 同意有尺码问题） | "Wish it got a female body a little more snug" |
| #378 | 4 | 好评出issue | not_breathable | —（gold 完全没标这个） | "threw it on in my kitchen while I was..." |
| #386 | 4 | 好评出issue | runs_too_small | size_fit_problem（gold 同意有尺码问题） | "BOOTS RUN SMALL. PURCHASE A LARGER SIZE." |

### 串台数 0

waders 50 条中没有命中已知串台 key（competitor_comparison / logistics_only / not_current_product / old_model_comparison）。

### 模块流向正确率 75.0%（第 3 次新增）

**算法**：
1. 从 fixture 的 `annotated_review_labels.module_routing` 提取 gold 模块路由
2. 系统输出：issue → `product_issue`，highlight → `product_highlight`
3. 对每个 TP label（系统输出 ∩ gold），检查系统模块是否在 gold 模块集合中
4. 正确路由数 / TP 总数 = 51/68 = 75.0%

**17 个路由错误分析**：
- audit_filter 违规 10 条：gold 标 `audit_filter` 但系统前台输出了（全是 `overall_satisfied`，内容为简短/通用好评如 "Un buen producto" / "Work great" / "Excellent" / "For good" 等）
- 其余 7 个：系统路由到 product_issue 但 gold 标 product_highlight（或反之），主要是 gold 的模块标注与系统 issue/highlight 类型不一致

**10 条 audit_filter 违规明细**：

| review_no | canonical_key | gold_modules | 内容片段 |
|-----------|---------------|-------------|----------|
| #355 | overall_satisfied | audit_filter | Un buen producto |
| #357 | overall_satisfied | audit_filter | Nice waders for the price. Will function as desired. |
| #360 | overall_satisfied | audit_filter | They're nice waders. |
| #369 | overall_satisfied | audit_filter | Work great |
| #371 | overall_satisfied | audit_filter, consumer_profile | Wader is good it keeps me dry... |
| #376 | overall_satisfied | audit_filter | functions as it should! the fitment is spot on! |
| #377 | overall_satisfied | audit_filter | For good |
| #380 | overall_satisfied | audit_filter | Awesome suit! |
| #382 | overall_satisfied | audit_filter | Seem to be working out well so far |
| #397 | overall_satisfied | audit_filter | Excellent |

**结论**：`overall_satisfied` 标签在信息密度极低的简短好评上被系统前台输出，但 gold 标注认为应进 `audit_filter`（审核过滤）。系统的审核层没有正确识别这些低信息密度片段。

**无法测量模块**：consumer_profile（9 个 gold 标注）、unmet_need（1 个 gold 标注）、purchase_motive（0 个）—— 系统当前未产生这些模块的输出，无法做模块流向对比。

### other 占比 13.9%（第 4 次新增）

**算法**：在 `enrich_aspects_json()` 中，occurrence 列表构建完成后，统计 `aspect_key == "other"` 的片段数。脚本从 `aspects_json._other_fragment_count` / `_total_fragment_count` 读取并求商。

**结果**：17 个 other 片段 / 122 个总片段 = **13.9%**，略低于 15% 通过线。

**17 个 other 片段来源**：
- 所有 `aspect_key` 映射为 `"other"` 的标签（`overall_satisfied`、`works_well_for_use_case`、`first_impression_positive`、`not_used_yet`、`overall_dissatisfied`、`not_for_heavy_brush` 等）
- 这些标签在 `_DEFAULT_ASPECT_MAP` 和 content-rule 中定义为 `aspect_key="other"`

## 新发现的「以为做好了其实没生效」

### 1. `allowed_aspects=None` 导致验证与生产不一致（第 2 次已修复）

**问题**：脚本传 `allowed_aspects=None` → `_validate_annotation` 回退到硬编码 `ASPECT_KEYS`（21 个通用 key），但 **不含** `waterproof`/`breathability`/`grip`/`seam_integrity` 等 waders 专属 key。

**修复**：`allowed_aspects = [a["key"] for a in taxonomy_aspects]`

### 2. LLM 零输出 `waterproof` aspect key——waders 类目最核心维度缺失

**现象**：修正后 LLM 的 aspect key 分布：
```
size_fit: 18, durability: 17, comfort: 14, value_for_money: 10,
ease_of_use: 7, build_quality: 6, other: 3, material: 3,
packaging: 2, customer_service: 1, shipping_damage: 1
```

缺失的 waders 核心 key：`waterproof`=0, `seam_integrity`=0, `breathability`=0, `grip`=0, `temperature_rating`=0, `boot_fit`=0, `mobility`=0, `accessory_storage`=0, `weight`=0。

**可能原因**：LLM prompt 中的 aspect block 列出了 21 个 key 和 boundary_note，但 LLM（gpt-4o-mini）倾向于用通用词（durability 代替 waterproof/seam_integrity），没有严格遵循 taxonomy 约束。

### 3. `stability` 不在 waders taxonomy 中，导致 2 条评论完全失败

**现象**：LLM 输出 `key: "stability"`，但 waders taxonomy 不含此 key → `schema_invalid` → 重试 2 次仍然输出 `stability` → 整条评论失败。

**影响**：2/50 = 4% 的评论完全没分析结果。

### 4. audit_filter 审核层对低信息密度好评无效（第 3 次发现）

**现象**：10 条简短/通用好评（如 "Work great" / "Excellent" / "For good"）的 `overall_satisfied` 标签被系统前台输出，但 gold 标注认为应进 `audit_filter`。

**影响**：模块流向正确率从可能的 89.7%（61/68）降到 75.0%（51/68）。

**建议**：审核层增加信息密度检查——当 evidence_span 字符数过短（如 < 20 字符）且不含具体产品维度关键词时，`overall_satisfied` 应降级到 audit。
