## 新发现的「以为做好了其实没生效」

### 1. `allowed_aspects=None` 导致验证与生产不一致（第 2 次已修复）

**问题**：脚本传 `allowed_aspects=None` → `_validate_annotation` 回退到硬编码 `ASPECT_KEYS`（21 个通用 key），但 **不含** `waterproof`/`breathability`/`grip`/`seam_integrity` 等 waders 专属 key。

**修复**：`allowed_aspects = [a["key"] for a in taxonomy_aspects]`

### 2. LLM 零输出 `waterproof` aspect key——waders 类目最核心维度缺失

**现象**：修正后 LLM 的 aspect key 分布：
```
size_fit: 18, durability: 17, comfort: 14, value_for_money: 10,
ease_of_use: 7, build_quality: 6, other: 3, material: 3,
packaging: 2, customer_service: 1, shipping_damage: 1
```

缺失的 waders 核心 key：`waterproof`=0, `seam_integrity`=0, `breathability`=0, `grip`=0, `temperature_rating`=0, `boot_fit`=0, `mobility`=0, `accessory_storage`=0, `weight`=0。

**可能原因**：LLM prompt 中的 aspect block 列出了 21 个 key 和 boundary_note，但 LLM（gpt-4o-mini）倾向于用通用词（durability 代替 waterproof/seam_integrity），没有严格遵循 taxonomy 约束。

### 3. `stability` 不在 waders taxonomy 中 → ✅ v2.4 已解决

**v2.1（旧）**：LLM 输出 `key: "stability"`，但 waders taxonomy 不含此 key → `schema_invalid` → 2 条评论失败。根因是 v2.1 prompt 硬编码家具 taxonomy（含 stability）。

**v2.4（新）**：动态注入 waders taxonomy block，模型不再输出 stability。schema_invalid 从 stability→0，替换为 polarity_invalid（1 条）+ key_invalid_'fit'（1 条）。Retry 已注入错误反馈。

### 4. audit_filter 审核层 → ✅ v2.4 已解决（overall_satisfied 移除）

**v2.1（旧）**：10 条简短/通用好评的 `overall_satisfied` 被系统前台输出 → 模块流向正确率仅 75.0%。

**v2.4（新）**：`overall_satisfied` 代码层阻挡不进前台 + gold 移除 → audit_filter 违规 = 0 → 模块流向正确率 92.5%。阶段 C 接入通用 audit_filter（LLM 语义判断，不依赖 waders 关键词或字符长度）。
