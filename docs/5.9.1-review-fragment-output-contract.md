# 5.9.1 评论片段输出契约

日期：2026-08-03

目标：先固定 AI 输出格式，不改 active 上传 / results / export / frontend 行为。新 5.9 主入口命名为 `review_fragment_*`，不沿用 `customer_label_v2_*` 或 `review_signal_*` 作为主入口。5.9.0 审计中的多模块分流经验可以借鉴，但 waders 旧规则只视为现有安全补丁，不作为新 5.9 质量依据继续扩张。

## 输出结构

单条评论输出为一个 review-level payload，核心字段是 `fragments`。每个 fragment 必须只包含以下 9 个片段级字段：

```json
{
  "fragment_text": "the noise cancellation is poor",
  "module": "product_issue",
  "aspect_key": "noise_cancellation",
  "polarity": "negative",
  "evidence_span": "noise cancellation is poor",
  "confidence": 0.95,
  "current_product_scope": "current_product",
  "can_aggregate": true,
  "reject_reason": null
}
```

review-level metadata 可以包含 `id`、`product_id`、`category`、`sub_category`、`rating`、`content`、`schema_version` 等，但这些不是片段契约本身。

## 字段含义

| 字段 | 类型 | 必填 | 含义 | 约束 |
|---|---|---:|---|---|
| `fragment_text` | string | 是 | 从原评论中截取的原文片段，不是总结改写。 | 非空；必须能在原评论中找到。 |
| `module` | enum | 是 | 片段先进入哪个理解模块。 | 见模块枚举。 |
| `aspect_key` | string/null | 是 | 标签候选 / aspect 候选。正式 taxonomy 命中时用 key；未覆盖时用 `candidate:<slug>` 或 `other`；纯过滤片段可为 `null`。 | `can_aggregate=true` 时必须非空，且不能是 `other` 或 `candidate:*`。 |
| `polarity` | enum | 是 | 片段情绪或方向。 | `positive` / `negative` / `mixed` / `neutral`。 |
| `evidence_span` | string | 是 | 支撑该判断的最小原文证据。 | 非空；必须能在 `fragment_text` 和原评论中找到。 |
| `confidence` | number | 是 | AI 对该片段结构化判断的置信度。 | 0-1。低置信片段默认不进入聚合。 |
| `current_product_scope` | enum | 是 | 证据是否属于当前产品及其上下文。 | 见 scope 枚举。 |
| `can_aggregate` | boolean | 是 | 是否允许进入对应模块的正式统计。5.9.1 只定义门禁，不接真实聚合链路。 | `false` 时必须给 `reject_reason`；`true` 时 `reject_reason=null`；同一评论内相同 `module + aspect_key + polarity` 只保留一次。 |
| `reject_reason` | enum/null | 是 | 不能聚合的原因。 | `can_aggregate=false` 时必须使用枚举；可人工审查。 |

## 枚举值

### module

| 值 | 说明 | 默认聚合策略 |
|---|---|---|
| `product_issue` | 当前产品的具体负向问题。 | 可聚合，前提是 evidence、scope、aspect 都通过。 |
| `product_highlight` | 当前产品的具体正向亮点。 | 可聚合，前提同上。 |
| `consumer_profile` | 人群、对象、使用者身份、使用场景。 | 可聚合到画像模块，不进产品问题/亮点 TOP。 |
| `purchase_motive` | 购买原因、选择场景、任务目标。 | 可聚合到购买动机模块。 |
| `unmet_need` | 用户期待、缺口、想要但未满足的需求。 | 可聚合到未满足需求模块。 |
| `comparison_or_other_product` | 竞品、旧产品、过往产品经验。 | 5.9.1 默认不聚合，只保留审计证据。 |
| `accessory_or_bundle` | 配件、赠品、外包装内附属物。 | 5.9.2 起允许进入后续 taxonomy gate；命中当前子品类配件/包装类 aspect 时可进主聚合，错贴主产品本体 aspect 时拦截。 |
| `logistics_support` | 物流、退货、客服、售后体验。 | 5.9.2 起包装/到货破损可进入后续 taxonomy gate；纯物流、客服、售后仍不应混入产品质量。 |
| `other_candidate` | 当前产品相关但 taxonomy 未覆盖或还需人工命名。 | 不聚合，进入后续 candidate / other 承接。 |
| `audit_filter` | 泛泛评价、无证据、不能判断、需拦截的片段。 | 不聚合。 |

### polarity

`positive`、`negative`、`mixed`、`neutral`。

### current_product_scope

| 值 | 说明 |
|---|---|
| `current_product` | 明确指当前被分析产品本体。 |
| `current_product_context` | 当前产品相关上下文，如购买原因、期待、使用任务。 |
| `non_product_context` | 人群、场景、时间、活动等非产品质量信息。 |
| `other_product` | 竞品、旧款、历史买过的其他产品。 |
| `accessory_only` | 只指配件或附属物；5.9.2 起可用当前 taxonomy 的配件类 aspect 聚合，不能错贴成主产品本体问题。 |
| `logistics_support` | 物流、包装运输、退换货、客服售后；5.9.2 起包装/到货破损可用当前 taxonomy 的包装类 aspect 聚合。 |
| `unclear` | 指代不清、泛泛评价、缺少可判断对象。 |

### reject_reason

`accessory_only`、`candidate_pending_review`、`confidence_low`、`evidence_missing`、`evidence_not_found`、`evidence_too_generic`、`fragment_too_vague`、`logistics_or_service`、`not_current_product`、`not_used_yet`、`other_product_or_competitor`、`schema_invalid`、`taxonomy_missing`、`taxonomy_out_of_scope`。

## 有效样例

| 原文片段 | module | aspect_key | polarity | evidence_span | scope | can_aggregate | reject_reason |
|---|---|---|---|---|---|---:|---|
| `I used them for 1 hour and they leaked like crazy` | `product_issue` | `water_leaks_through` | `negative` | `leaked like crazy` | `current_product` | true | null |
| `battery life is great` | `product_highlight` | `battery_life` | `positive` | `battery life is great` | `current_product` | true | null |
| `Bought as a gift for my boyfriend` | `consumer_profile` | `gift_recipient_partner` | `neutral` | `gift for my boyfriend` | `non_product_context` | true | null |
| `Compared with AirPod 3 and 2nd generation Pros` | `comparison_or_other_product` | `other_airpods_comparison` | `mixed` | `AirPod 3 and 2nd generation Pros` | `other_product` | false | `other_product_or_competitor` |

## 无效样例

| 输出 | 为什么无效 | 应如何处理 |
|---|---|---|
| `module=other_candidate`、`aspect_key=candidate:boot_seam_leak`、`can_aggregate=true` | candidate 还没人工确认，不能直接进正式统计。 | `can_aggregate=false`，`reject_reason=candidate_pending_review`。 |
| `evidence_span=battery lasts forever`，但片段是 `The fit is great` | 证据不在原文片段中，属于无证据或错配。 | 降级为 `can_aggregate=false`，`reject_reason=evidence_not_found`。 |
| `module=comparison_or_other_product`、旧产品 leaked、`can_aggregate=true` | 旧产品问题会污染当前产品。 | `can_aggregate=false`，`reject_reason=other_product_or_competitor`。 |
| `fragment_text=Overall good`、`aspect_key=overall_satisfied`、`can_aggregate=true` | 片段过泛，缺少可追溯的具体属性。 | `module=audit_filter`，`can_aggregate=false`，`reject_reason=fragment_too_vague`。 |

### 重复亮点处理

同一条评论重复表达同一个产品亮点时，不重复计数。以 `module + aspect_key + polarity` 作为评论内去重键：

- 两个片段表达同一亮点：合并成一个连续的原文片段，保留覆盖更完整的证据。
- 无法合并时：保留置信度更高或证据更具体的一条。
- 同一 aspect 出现正负两种极性时，不能静默合并；应保留为正负两个片段，交由后续冲突审核。

## 5.9.1 验收结论

这份契约已经把 AI 输出从“直接吐 Customer Issue / Customer Label”改成“原文片段 -> 模块 -> 标签候选 -> 证据 -> 是否可聚合”。它足够进入 Erika 人工验收：重点看片段是否拆得自然、模块是否分对、`can_aggregate=false` 的拦截理由是否符合产品直觉。
