## §2 证据门禁 — 原 P0 判定已撤回（系脚本设计假象）

### 2.1 原判定为何是错的

上一版报告将「证据门禁缺失」列为 P0 阻断项，**该判定已撤回**。原因如下：

**离线脚本与生产链路的调用方式不同**：
- 离线脚本对每条评论**无条件**调了全部 9 个 label key 的 resolver
- 生产链路不这么干：只对**已存在且已带 evidence 的 occurrence** 调 resolver（见 `backend_api/app/services/specific_issue.py:4393-4409`）
- TOP10 计数门禁已经同时要求 `verified_evidence` + `not cluster_propagated` + `evidence_span`（见 `_is_frontstage_countable_occurrence`，`specific_issue.py:3653-3663`）
- 无证据标签进不了 TOP10，那条「标签无原文依据仍进入 TOP10」停止规则实际**没有被触发**

**补充事实**：`validate_review_fragment_evidence()`（`review_fragment_evidence_gate.py:249`）在 active 路径确实没有调用者，唯一调用方是 5.9.4 实验模块 `review_fragment_candidate_multimodule.py:990`。但 active 路径有自己的一套证据校验（`_evidence_verified`，`specific_issue.py:956-957`，propagated 时返回 False），所以**不构成缺口**。

### 2.2 真正查出来的问题：Cluster 传播污染

clueai-dev 的 waders occurrence 中 **31/32（96%）的 `evidence_span` 不出现在该条评论自己的原文里**，全部来自 cluster 0 的代表 `id=479`（一条好评）。

**根因**：HDBSCAN 聚类把代表的标签 + 证据传播给全体成员 → `backend_api/app/services/clustering.py:229` 设 `cluster_propagated: True`。cluster 0 把好评差评混进了同一簇（rep=479 是好评，成员 508 是强负评）。

**最说明问题的案例 id=508**：
- 原文：「Both feet are **leaking** around where the boot connects to the wader. the boot is also extremely **uncomfortable**」
- 实际拿到：`uncomfortable_fit`，evidence =「stayed warm, dry and comfortable the whole time」（与原文相反）
- 它真正的 `water_leaks_through`（真 hard case）**漏标了**

另一例 id=524：`not_breathable` 配正向证据文本。

**失效形态**：因为 TOP10 门禁会把 propagated 全部剔掉，前台的表现是**漏标 / TOP10 被掏空**，不是无中生有上前台。这不是 scope 层的问题，是聚类传播层在 dev 数据上的过度传播。

### 2.3 对 5.9.7 剩余出口条件的影响

5.9.7 章程要求的另外两条 ——「TOP10 是否符合产品直觉」和「行动中心 handoff」—— 离线验不了，**且用当前 dev 数据也验不了**：96% 被剔掉后 waders 的 TOP10 接近空。

## §8 发现的真实问题 → 修复方向

本次验收发现的真实问题不是"标签范围错了"（scope 全对），也不是"证据门禁缺失"（生产链路已有），而是**聚类传播过度污染**：

| 类型 | 严重度 | 描述 | 修复方向 |
|------|--------|------|---------|
| **Cluster 传播污染** | P0 | waders 96% occurrence 的 evidence_span 来自 cluster 代表而非自身原文。cluster 0 混入好评差评，导致 id=508（真实漏水投诉）拿到反向证据、漏标 `water_leaks_through` | 关掉或收紧验收批次的 cluster 传播，重新分析产出非传播 TOP10 |
| **交易标签无差别全局** | P2 | 4 个 txn_universal 标签对所有品类生效，但大多数评论不涉及交易体验 | 证据门禁会自然解决：没谈物流的评论不会标 `late_shipping` |

这些不是 registry proposal 能解决的问题（标签定义和 scope 都对），而是**聚类传播策略需要在 dev 数据上调整**。
