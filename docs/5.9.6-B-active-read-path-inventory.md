# 5.9.6-B Active/Read-Path Inventory and Freeze

日期：2026-08-06
范围：仅代码审计、链路对账与冻结决策；不修改 active 行为，不调整 9 个 approved label 的 scope。

## 结论

`5.9.6-B` 已有一部分 active frontstage/read-path 代码，但它们是旧 `customer_label_v2` / `review_signal` / `specific_issue` 兼容链路，不是 `5.9.6-A` 的 `review_fragment_label_catalog` + registry resolver + scope gate 的 active 接入。

本次完成的是对账与冻结交付，不代表 active 接入完成。当前 active 结果页、导出、worker 写入、定时摘要和前端客户端聚合均未调用 5.9.6-A resolver；其中面向用户的结果、导出和前端读取路径，以及会生成行动/推送的定时路径，均是 `5.9.6-D` 必须处理的 blocker。

## 5.9.6-D Blocker

下列路径目前绕过 `review_fragment_label_catalog.resolve_formal_label*()`，或者根本没有 formal scope decision。局部 evidence、display、aspect 或 waders guard 不能替代 registry/resolver/scope gate。

1. `analysis.py` 的 session 与 aggregated results 路径，及其 `build_results_insights()` 下游聚合。
2. `export.py` 的 module/full export，以及 `review_analyzer/exporter.py` 的 XLSX/CSV/TOP10 normal display。
3. `specific_issue.py` 的 v1/v2/review-signal/legacy occurrence selection、TOP10 row construction 与 decorator。
4. `customer_label_v2_frontstage.py` 和 `review_signal_frontstage.py` 对 stored shadow 的选择，当前均不解析 registry formal key。
5. `workers/jobs.py` 的 `enrich_aspects_json()` 写入和 `_post_analysis_smart_push()` 的 issue/highlight 统计。
6. `workers/periodic_jobs.py -> review_analyzer/notifier.py` 的 periodic digest、snapshot、escalation/action handoff。
7. `frontend/src/lib/customer-labels.ts` 的 payload fallback、detail/TOP10/client download。
8. `database.py` compact read：future formal artifact 必须保留 registry version、label source、scope decision 等必要 provenance，不能像 v2 shadow 一样静默丢失。

此外，当前 registry 的 9 个 approved label 都是 `category_keys: ["*"]` 与 `sub_category_keys: ["*"]`。这是 5.9.6-D 的数据治理 blocker；本次只记录，不直接修正。

## 5.9.6-D 明确输入

### 必须接入同一 scope gate 的入口

1. results routes：在结果页 comments 进入 insights/TOP10 前，按当前 category/sub_category、证据与 registry version 获取 formal rows。
2. export routes：module export、full XLSX、CSV、TOP10 和 normal review rows 使用同一 formal rows；audit sheet 可保留 rejected/candidate，但必须标识为 audit-only。
3. core selector：`iter_specific_issue_occurrences()`、`iter_customer_highlight_occurrences()`、`build_*_rows()` 和 decorator 不再把旧 catalog/read model 当 formal truth。
4. frontstage adapters：v2/review-signal 只能提供候选或兼容 evidence，最终 display key 必须由 Registrar 重新 resolve。
5. worker：写入 versioned formal artifact，并在写入时记录 resolver 结果、scope decision 和 evidence decision；smart push 只能消费该 artifact。
6. periodic/action：digest、notifier、snapshot/escalation/action handoff 改读 formal rows，或在迁移前明确停用 formal label 推送扩张。
7. frontend：只渲染后端已 gate 的 formal rows；legacy/v2 fallback 不能绕开 scope 决策。
8. compact DB read/cache：保证 formal provenance 不丢失，并把 registry version 纳入 results/analysis cache 语义。

### 必须补的测试

1. registry schema：无 `scope_reason` 的 wildcard、没有正反例的 approved label、`allowed_aspect_keys` 不在 taxonomy 中时 fail-closed。
2. resolver：category/sub_category 缺失、scope 不匹配、blocked context、错误 aspect、未验证 evidence 均不返回正式 label。
3. 跨类目负例：`waterproof`、`seam_integrity`、`accessory_storage` 不得在不适用品类显示。
4. results/export parity：同一 comment 在 session results、aggregated results、module export、full XLSX/CSV 得到相同的 formal key、scope decision 和 evidence eligibility。
5. frontstage isolation：v2/review-signal stored shadow 的 candidate/audit/non-product/unverified signal 不能借 read model 绕过 resolver；waders/session guard 保持 fail-closed。
6. worker/periodic/action：worker 不能写无 resolver provenance 的 formal row；smart push 与 periodic digest 不再直接把 legacy tags 当正式标签。
7. DB compact read：formal artifact 的 registry version、label source、scope/evidence decision 在 slim comments 下仍存在；v2 shadow 丢失应有显式 fallback coverage。
8. frontend：`customerLabelOccurrences()`、detail、client TOP10/download 不会用 legacy/v2 payload 重新展示 scope-rejected formal label。
9. cache：registry version 改变后结果缓存失效；该项与 5.9.6-B.1 联动。
10. static isolation：active routes/exporter/workers 不得直接依赖实验模块标签常量；迁移完成后不得遗留 raw `issue_tag` / `highlight_tag` 的 formal display path。

建议沿用并扩展现有 `test_review_fragment_label_catalog.py`、`test_database_read_path.py`、`test_customer_label_v2_frontstage_isolation.py`、`test_review_signal_step9_1_frontstage_guarded.py`，并新增 results/export/worker/periodic/frontend parity 覆盖。

## 冻结边界

- 不在 5.9.6-B 修改任何 active flag、session allowlist、`waders` guard 或 existing fallback 行为。
- 不在 5.9.6-B 新增旧 `customer_label_catalog` label、alias、waders content rule 或 frontstage scope。
- 不在 5.9.6-B 修正 registry 中 9 个 approved label 的 `["*"]` scope；该工作属于 5.9.6-D。
- 5.9.6-B 不标记为 active 接入完成。它的产出是现状 inventory、兼容层冻结和 5.9.6-D 的明确改造输入。
