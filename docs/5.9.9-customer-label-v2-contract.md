# 5.9.9 Customer Label System v2: 输出契约与回退策略

日期：2026-07-30

状态：Step 1 完成

## 1. 目标

Customer Label System v2 的目标，是把 Customer Issue / Customer Label 从“逐类目手写规则主生成”升级为：

```text
LLM evidence-first candidate generation
  -> deterministic verifier
  -> display / candidate / audit split
  -> maturity-level display gate
```

v2 不追求在 MVP 前把 89 个 sub_category 都做成 waders 级 L3。它优先保证：

- 已验证类目高精度展示。
- 未验证类目安全降级。
- 候选标签可审核、可追踪、可沉淀为 gold regression。
- 前台永远不展示无 evidence、cluster propagated、旧产品/他牌/配件污染或 aspect 冲突的确定标签。

## 2. 非目标

- 不在本阶段训练 ABSA 小模型。
- 不为每个 sub_category 手写 3-5 天规则。
- 不替换 5.9.8 已通过的 waders safety gate 和 gold regression。
- 不在 Step 1 调用 production LLM、生产上传、生产重分析或 credit 写路径。
- 不在 Step 1 建复杂审核后台；candidate pool MVP 可先是 DB 表、CSV/XLSX 导出或最小后台页。

## 3. 数据分层

| 层 | 用途 | 是否前台展示 |
|---|---|---|
| `label_candidates` | LLM / fallback 生成的原始候选标签 | 否 |
| `verified_occurrences` | verifier 在当前评论中定位并验证后的 occurrence | 仅通过 display gate 后展示 |
| `display_occurrences` | 进入 Top10、单条明细、raw frontstage、single-tag download 的确定标签 | 是 |
| `audit_occurrences` | 被降级、阻断、legacy fallback、cluster propagated、低置信或证据失败的记录 | 否，仅审计 |
| `candidate_pool_items` | 需要 Erika 或后续审核机制判断的新标签/冲突标签/高影响异常 | 否，仅审核 |

## 4. LLM 输出契约

LLM 只负责语义理解和候选生成，必须输出 evidence-first JSON。规则层不再要求为每个 label 维护完整关键词生成库，但会严格验证 evidence 和上下文。

### 4.1 顶层字段

```json
{
  "customer_label_schema_version": "2.0",
  "prompt_version": "customer-label-v2.0",
  "model": "gpt-4o-mini",
  "source": "llm",
  "sub_category": "waders",
  "category": "outdoor",
  "language": "en",
  "label_candidates": []
}
```

### 4.2 `label_candidates[]`

```json
{
  "label_type": "issue",
  "canonical_label_key": "water_leaks_through",
  "raw_label": "does not keep water out",
  "display_label_en": "Water Leaks Through",
  "display_label_zh": "防水性差",
  "aspect_key": "waterproof",
  "polarity": "negative",
  "evidence_candidate": "They do not keep you dry",
  "evidence_start": null,
  "evidence_end": null,
  "confidence": 0.88,
  "reason": "The review directly says the product does not keep the wearer dry."
}
```

Required fields:

- `label_type`: `issue` or `highlight`
- `canonical_label_key`: stable snake_case key; unknown labels use `candidate:<slug>`
- `raw_label`: LLM's natural-language label before canonical mapping
- `aspect_key`: taxonomy aspect key or `unknown`
- `polarity`: `negative`, `positive`, `mixed`, or `neutral`
- `evidence_candidate`: shortest review text span that proves the label
- `confidence`: `0.0` to `1.0`
- `reason`: short explanation for audit and debugging

Optional fields:

- `display_label_en`
- `display_label_zh`
- `evidence_start`
- `evidence_end`
- `subcategory_specificity`: `generic`, `category`, or `sub_category`
- `risk_flags`: list such as `old_product_context`, `accessory_context`, `uncertain_aspect`, `implicit_claim`

### 4.3 Hard JSON Requirements

- Output must be valid JSON with no markdown wrapper.
- `label_candidates` must be an array, even when empty.
- Every candidate must include an `evidence_candidate`; if no evidence exists, the LLM should not emit that candidate.
- One candidate maps to one canonical label and one evidence span.
- Do not infer durability, fit, waterproofing, value, or material quality from generic praise.
- Do not convert historical comparison, old product, other brand, shipping, packaging, or accessory-only issues into current product body labels.

## 5. Verifier 输入输出契约

Verifier is deterministic. It receives one review and one or more candidates, then emits verified occurrences and downgrade reasons.

### 5.1 Input

```json
{
  "review_id": 123,
  "content": "They do not keep you dry.",
  "rating": 2,
  "category": "outdoor",
  "sub_category": "waders",
  "schema_version": "2.0",
  "ruleset_version": "customer-label-verifier-v2.0",
  "maturity_level": "L3_sub_category",
  "label_candidates": []
}
```

### 5.2 Output

```json
{
  "review_id": 123,
  "schema_version": "2.0",
  "ruleset_version": "customer-label-verifier-v2.0",
  "verified_occurrences": [],
  "display_occurrences": [],
  "audit_occurrences": [],
  "candidate_pool_items": []
}
```

### 5.3 Occurrence Fields

```json
{
  "label_type": "issue",
  "canonical_label_key": "water_leaks_through",
  "display_label_en": "Water Leaks Through",
  "display_label_zh": "防水性差",
  "aspect_key": "waterproof",
  "polarity": "negative",
  "evidence_span": "do not keep you dry",
  "evidence_start": 5,
  "evidence_end": 24,
  "confidence": 0.88,
  "source": "llm",
  "source_review_allowed": true,
  "evidence_verified": true,
  "aspect_allowed": true,
  "context_allowed": true,
  "maturity_allowed": true,
  "display_allowed": true,
  "cluster_propagated": false,
  "legacy_fallback": false,
  "downgrade_reasons": [],
  "verifier_reasons": ["evidence_exact_match", "subcategory_l3_allowed"]
}
```

## 6. Display Gate

An occurrence may enter frontstage only when all conditions are true:

| Field | Required value |
|---|---|
| `source_review_allowed` | `true` |
| `evidence_verified` | `true` |
| `evidence_span` | non-empty and locatable in current review |
| `cluster_propagated` | `false` |
| `legacy_fallback` | `false`, except explicitly allowlisted generic fallback |
| `aspect_allowed` | `true` |
| `context_allowed` | `true` |
| `maturity_allowed` | `true` |
| `display_allowed` | `true` |

If any condition fails, the occurrence must not enter:

- Top10 counts
- Top representative evidence
- single review detail chips
- raw review frontstage columns
- single-tag download rows

It may still enter `audit_occurrences` or `candidate_pool_items`.

## 7. Downgrade Reasons

Use stable reason codes so exports, tests, candidate pool and warnings can share one vocabulary.

| Code | Meaning |
|---|---|
| `invalid_json` | LLM output cannot be parsed |
| `schema_invalid` | JSON parsed but required fields are missing or malformed |
| `evidence_missing` | Candidate has no evidence text |
| `evidence_not_found` | Evidence cannot be located in current review |
| `evidence_too_generic` | Evidence is generic praise/complaint and does not prove the label |
| `source_review_blocked` | Evidence belongs to another product, old product, other brand, packaging, shipping, service, or accessory-only context |
| `aspect_blocked` | Candidate label and aspect conflict |
| `context_blocked` | Negation, comparison, hypothetical, not-used-yet, or mixed-context guard blocks display |
| `maturity_blocked` | Current sub_category maturity does not allow this label specificity |
| `confidence_low` | Confidence below display threshold |
| `unknown_label` | Canonical label is not in active catalog |
| `cluster_propagated` | Candidate came from cluster propagation rather than the source review |
| `legacy_fallback` | Candidate came from v1 fallback and is not display allowlisted |

## 8. 类目成熟度

| Level | Scope | Frontstage Strategy | Entry Criteria |
|---|---|---|---|
| `L0_unknown` | 未接入或未验证 category/sub_category | 默认不进入 display；当前 explicit-safe hook 为空，候选进入 audit/candidate pool | 未命中 maturity config，或显式降级 |
| `L1_generic` | 只具备通用安全展示能力的 category | 仅展示 generic-safe highlights；issues、category/sub_category 细粒度标签进入 audit/candidate pool | category 已在 10 大类灰度中，但尚无 category-safe label 回归 |
| `L2_category` | category 级 aspect/taxonomy 边界稳定 | 只展示高置信、强 evidence、低风险 category-safe 基础标签；sub_category 细粒度标签仍需候选审核 | category catalog + aspect mapping 通过 focused regression |
| `L3_sub_category` | 高价值/高上传量/已验收 sub_category | 展示细粒度 Customer Issue / Customer Label | 30-50 条 blind gold 或等价真实上传抽查通过 |

Initial maturity:

- `outdoor/waders`: `L3_sub_category`
- `home`、`3c`、`apparel`、`outdoor`、`beauty`、`kitchen`: `L2_category`
- `baby`、`pet`、`automotive`、`office`: `L1_generic`
- Other category/sub_category: `L0_unknown`

## 9. Fallback Strategy

| Failure / State | Action |
|---|---|
| LLM unavailable | Use v1 rules/fallback only for explicitly allowlisted generic or L3 labels; mark `legacy_fallback=true` |
| LLM invalid JSON | Do not display LLM candidates; create audit item with `invalid_json`; optionally run allowlisted fallback |
| Candidate evidence missing | Candidate/audit only, never display |
| Evidence not found in current review | Candidate/audit only, never display |
| Aspect conflict | Candidate/audit only unless verifier can deterministically correct aspect |
| Old product / other brand / accessory-only context | Candidate/audit only; for waders, accessory pocket/phone-case water ingress cannot become overall waterproof issue |
| Not used yet / hypothetical | Candidate/audit only for performance labels; may display `not_used_yet` if catalog allows |
| Unknown canonical label | Candidate pool only, with `unknown_label` |
| Low maturity for fine-grained label | Candidate/audit only until maturity upgrade |
| Existing cache has old schema | Re-verify on read path; frontstage uses only current verified display occurrences |

## 10. Export Contract

All user-facing paths must consume `display_occurrences` only:

- Results page Top10
- Single review detail
- single-tag download
- raw review frontstage columns

Audit exports may include `audit_occurrences` and `candidate_pool_items`, but field names must clearly indicate audit/candidate status.

Required raw/frontstage fields:

- `Customer Issue`
- `Canonical Issue Key`
- `Customer Label`
- `Canonical Highlight Key`

Required audit fields:

- `Audit Customer Issue`
- `Audit Canonical Issue Key`
- `Audit Customer Label`
- `Audit Canonical Highlight Key`
- `Audit Evidence Span`
- `Audit Evidence Verified`
- `Audit Cluster Propagated`
- `Audit Display Allowed`
- `Audit Downgrade Reasons`
- `Audit Source`
- `Audit Schema Version`
- `Audit Ruleset Version`

## 11. Candidate Pool MVP

Minimum candidate item:

```json
{
  "candidate_id": "uuid",
  "review_id": 123,
  "session_id": 456,
  "product_id": "TIDEWE-...",
  "category": "outdoor",
  "sub_category": "waders",
  "label_type": "issue",
  "canonical_label_key": "candidate:boot_seam_leak",
  "raw_label": "boot seam leaks",
  "evidence_candidate": "leaked around the boot seam",
  "confidence": 0.79,
  "downgrade_reasons": ["unknown_label"],
  "top_impact_score": 0.42,
  "review_status": "pending"
}
```

Allowed review actions:

- `accept`
- `reject`
- `correct_label`
- `correct_evidence`
- `needs_new_label`
- `ignore`

Accepted/corrected candidates may later become:

- catalog entries
- aliases
- boundary notes
- few-shot examples
- gold regression fixtures
