# 5.9.2 Taxonomy 白名单契约

日期：2026-08-05

目标：在 5.9 新主线里增加纯 taxonomy whitelist 校验能力，防止 AI 把当前 `sub_category` 之外的自由 aspect 直接送入正式聚合。本阶段不接入 active upload、worker、results、export 或 frontend。5.9.4.1-A 明确：5.9.2 继续负责 `aspect_key` 证据维度白名单，不负责生成卖家可读 TOP10 key，也不推翻 5.9.1 基础契约。

## Taxonomy 来源

正式来源是已有 `category_aspect_taxonomy` 表，通过 `backend_api/app/services/taxonomy_loader.py` 的 `resolve_aspects(sub_category)` 读取。

5.9.2 新模块为 `backend_api/app/services/review_fragment_taxonomy_whitelist.py`：

- 新命名入口：`review_fragment_taxonomy_*`。
- 不使用 `customer_label_v2_*` 或 `review_signal_*` 作为主入口。
- 复用现有 taxonomy loader，不新建标签库。
- `taxonomy_loader` 的 fallback base aspect 只用于旧 prompt 兼容；在 5.9.2 whitelist 中，`hit=False` 一律视为 `taxonomy_missing`，不得正式聚合。

测试 fixture 使用 `data/taxonomy/v1.0/outdoor/waders.yaml` 和 `data/taxonomy/v1.0/home/床架.yaml` 模拟 `category_aspect_taxonomy` 行。

## 三层标签边界

5.9.2 只校验第二层 `aspect_key`，三层职责不可互换：

| 层 | 5.9.2 的处理 |
|---|---|
| `module` | 读取上游路由结果，决定是否属于产品问题 / 亮点、配件 / 包装等可进入本 gate 的模块。它不是 taxonomy aspect。 |
| `aspect_key` | 从当前 `sub_category` 的 `category_aspect_taxonomy` 读取和校验的证据维度，例如 `seam_integrity`、`accessory_storage`。 |
| `issue_key` / `action_label_key` | 后续 artifact 的卖家可读正式 TOP10 key，例如 `water_leaks_through`、`accessory_leak`、`late_shipping`。它们不是 taxonomy aspect，不能作为本阶段白名单来源。 |

因此，`water_leaks_through` 被传入 `aspect_key` 时必须按库外 aspect 处理；未来若经人工治理批准，它可以作为 `issue_key` 映射到 `aspect_key=seam_integrity`。所有内部 key 统一使用英文稳定 key，中文和前台英文展示通过 display label mapping 生成，不单独输出中文 key。

正式 TOP10 的业务定义是“卖家可行动问题 / 亮点 TOP10”。taxonomy whitelist 只回答“原文证据属于哪个允许的 aspect”，不单独回答“这个 aspect 最终用什么卖家标签展示”。因此，配件、履约、尺码表、详情页等卖家可行动问题是否拥有 approved `issue_key` / `action_label_key`，由 5.9.4.1-B 的 artifact mapping 处理；5.9.2 不制造临时 key，也不把缺少 mapping 的片段伪装成正式 TOP10。

## sub_category 解析规则

- 以当前产品 review-level payload 的 `sub_category` 为准。
- `category` 只保留用于审计和人工表格，不作为 aspect 白名单来源。
- `sub_category` 为空、缺失或无法判断时，返回 `taxonomy_missing`。
- `resolve_aspects(sub_category)` 返回 `hit=False` 时，返回 `taxonomy_missing`，即使 loader 给了 fallback base aspect。
- 白名单只保留正式 aspect key：排除空 key、`other`、`candidate:*`。
- 配件 / 包装现在按 Erika 最新口径允许进入后续正式 artifact，但必须使用当前子品类 taxonomy 中明确的配件、零件、包装、到货损坏类 aspect，例如 `accessory_storage`、`missing_parts`、`packaging`、`shipping_damage`。
- 包装 / 到货损坏不是按品类特殊处理：`waders` 和 `床架` 只要当前 taxonomy 命中 `packaging` / `shipping_damage` 都可以继续聚合。纯客服、退款、退货等服务纠纷仍不进入产品问题 / 亮点；`late_shipping`、`confusing_size_chart`、`detail_page_misleading` 这类卖家可行动标签属于后续 artifact mapping，不应被误写成 taxonomy aspect。

## 状态枚举

| 状态 | 触发条件 | 处理 |
|---|---|---|
| `allowed` | `product_issue` / `product_highlight` 命中当前产品 taxonomy；或配件 / 包装片段命中当前 taxonomy 中的 `accessory_storage`、`missing_parts`、`packaging`、`shipping_damage` 等交付可优化 aspect。 | taxonomy gate 允许继续聚合；不主动把上游已拦截片段改成可聚合。 |
| `taxonomy_out_of_scope` | `aspect_key` 不在白名单、为 `other`、为 `candidate:*`；或配件 / 包装片段被错贴成主产品本体 aspect。旧产品、竞品、消费者画像、泛泛审计片段仍由 module / scope / evidence gate 拦截，不把它们混称为 taxonomy 事实。 | `can_aggregate=false`；库外 aspect 使用 `taxonomy_out_of_scope`，candidate 使用 `candidate_pending_review`。原文证据仍可保留供后续 candidate / artifact 审核。 |
| `taxonomy_missing` | `sub_category` 缺失、无法判断，或 taxonomy loader 未命中当前子品类。 | `can_aggregate=false`，`reject_reason=taxonomy_missing`。 |

## 无效样例

| fragment | module | aspect_key | 为什么拦截 |
|---|---|---|---|
| `leaked like crazy` | `product_issue` | `water_leaks_through` | 这是旧 customer issue key，不是 `waders` taxonomy aspect key。 |
| `Great for light fly fishing` | `product_highlight` | `works_well_for_use_case` | 库外标签，需降级 candidate / other，不能直接进正式亮点。 |
| `I have not used them in water` | `audit_filter` | `other` | `other` 不得直接聚合。 |
| `living room try on` | `other_candidate` | `candidate:living_room_try_on` | candidate 未人工确认，不得直接聚合。 |
| `old AirPod 3 battery died quickly` | `comparison_or_other_product` | `battery_life` | 旧产品污染，不得映射成当前产品问题。 |
| `phone case leaked` | `accessory_or_bundle` | `waterproof` | 配件问题可以统计，但不能错贴成主产品防水问题；应使用 `accessory_storage` 等配件 aspect。 |
| `small leaks` with empty `sub_category` | `product_issue` | `waterproof` | taxonomy 缺失，fail closed。 |

备注：使用场景、人群、购买原因和期待缺口不走产品问题 / 亮点 taxonomy 白名单硬判。它们会并入 5.9.4「candidate / other + 多模块承接」：`consumer_profile` 流向消费者画像，`purchase_motive` 流向消费动机，`unmet_need` 流向未满足需求。卖家可行动问题仍需经过原文证据 gate 和后续 approved label mapping，不能因为 aspect 命中就自动生成中文或英文展示 key。

## 验收结论

5.9.2 现在具备进入 Erika 人工验收的最小能力：产品问题 / 亮点及可行动的配件、包装、到货维度只有命中当前 `sub_category` taxonomy 的 `aspect_key` 才能继续进入后续聚合；库外 aspect、candidate、other 和 taxonomy 缺失 fail closed。`issue_key` / `action_label_key` 仍是后续 artifact 的卖家可读层，不会污染 taxonomy 白名单。纯客服、退款、退货、旧产品 / 竞品和消费者画像的边界由 module / scope / evidence gate 继续负责。

本阶段只更新 whitelist 定义和验收说明，不接入 active upload、worker、results、export 或 frontend，也不改变 5.9.0 waders 隔离决策点。
