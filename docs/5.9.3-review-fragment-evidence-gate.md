# 5.9.3 原文证据门禁

日期：2026-08-04

目标：在 5.9.1 输出契约和 5.9.2 taxonomy 白名单之后，增加独立的原文证据门禁，防止无原文依据、泛化总结、旧产品 / 竞品 / 物流售后污染进入正式聚合。本阶段不接入 active upload、worker、results、export 或 frontend。

## 模块

新增实验模块：

- `backend_api/app/services/review_fragment_evidence_gate.py`
- 测试 fixture：`backend_api/tests/fixtures/review_fragment_evidence_5_9_3_samples.json`
- 单元测试：`backend_api/tests/test_review_fragment_evidence_gate.py`

版本：

- `review-fragment-evidence-gate.5.9.3`
- `review-fragment-evidence-gate-samples.5.9.3`

该模块只提供纯函数，不被上传、worker、结果页、导出或前端引用。

## 输入

每个片段仍沿用 5.9.1 的字段：

`fragment_text`、`module`、`aspect_key`、`polarity`、`evidence_span`、`confidence`、`current_product_scope`、`can_aggregate`、`reject_reason`

review 级输入需要额外提供原始 `review_text`，并传入 5.9.2 解析出的当前 `sub_category` taxonomy whitelist。

## 输出

门禁为每个片段补充 / 修正：

| 字段 | 含义 |
|---|---|
| `evidence_valid` | `evidence_span` 是否是可追溯的原文证据。空、原文找不到、泛泛总结硬拆具体标签时为 `false`。 |
| `evidence_source` | `fragment_text`、`review_text`、`empty`、`not_found`。优先命中 `fragment_text`，否则允许命中原始 `review_text`。 |
| `can_aggregate` | 是否允许进入正式聚合。candidate / other 即使 evidence 有效也保持 `false`。 |
| `reject_reason` | 拦截原因，例如 `evidence_missing`、`evidence_not_found`、`evidence_too_generic`、`other_product_or_competitor`、`logistics_or_service`、`accessory_only`、`candidate_pending_review`。 |

测试辅助输出还包含 `taxonomy_status`，用于确认 evidence gate 与 5.9.2 whitelist 的组合结果。

## 门禁规则

1. `evidence_span` 为空：`evidence_valid=false`，`reject_reason=evidence_missing`。
2. `evidence_span` 既不在 `fragment_text`，也不在原始 `review_text`：`evidence_valid=false`，`reject_reason=evidence_not_found`。
3. `Great product`、`Nice product`、`Overall good` 等泛泛好评，不能硬拆成 `waterproof`、`comfort`、`durability` 等具体亮点：`reject_reason=evidence_too_generic`。
4. 旧产品、竞品、历史产品证据只进入对比 / 审计，不进入当前产品问题或亮点：`reject_reason=other_product_or_competitor`。
5. 物流、客服、退款、退货等证据不能当成当前产品问题 / 亮点：`reject_reason=logistics_or_service`。
6. 配件证据可以聚合，但必须使用配件 aspect，例如 `accessory_storage`；不能把 `phone case leaked` 贴成当前 waders 的 `waterproof` 问题。
7. 包装、到货损坏可以聚合，但必须使用 `packaging` / `shipping_damage` 等对应 aspect。
8. `candidate:*` / `other` 必须保留 evidence，但不进入正式 TOP10。

## 10 条 fixture 覆盖

| # | 样例 | 检查点 | 结果 |
|---:|---|---|---|
| 1 | `current-product-evidence-allowed` | 当前产品接缝漏水证据存在 | `seam_integrity` 可聚合。 |
| 2 | `rewritten-evidence-not-found-blocked` | evidence 是 LLM 改写 / 原文不存在 | `evidence_not_found`。 |
| 3 | `empty-evidence-blocked` | 空 evidence | `evidence_missing`。 |
| 4 | `generic-praise-hard-split-blocked` | `Great product` 被拆成多个具体亮点 | `evidence_too_generic`。 |
| 5 | `old-product-and-current-product-separated` | 旧 Brand X waders 漏水 + 当前产品 dry | 旧产品拦截，当前产品防水亮点可聚合。 |
| 6 | `logistics-service-pollution-blocked` | shipping / customer service 污染 | 不算当前产品问题或亮点。 |
| 7 | `accessory-evidence-object-boundary` | phone case 漏水 | `accessory_storage` 可聚合；不得变成 waders `waterproof` 问题。 |
| 8 | `packaging-arrival-damage-correct-aspects` | box damaged / repair patch missing | `shipping_damage`、`accessory_storage` 可聚合。 |
| 9 | `candidate-and-other-retain-evidence` | candidate / other 证据保留 | evidence 有效，但不进正式 TOP10。 |
| 10 | `review-text-source-evidence-allowed` | evidence 只在原始 review_text 中 | `evidence_source=review_text`，可继续聚合。 |

## 验收结论

5.9.3 已具备最小可验收能力：正式聚合标签必须能追溯到原文证据；无证据、泛化总结、旧产品 / 竞品、物流售后、配件错贴主产品的问题都会 fail closed；candidate / other 仍保留 evidence，等待 5.9.4 治理。
