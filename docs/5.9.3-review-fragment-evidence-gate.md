# 5.9.3 原文证据门禁

日期：2026-08-05

目标：在 5.9.1 输出契约和 5.9.2 taxonomy 白名单之后，增加独立的原文证据门禁，防止无原文依据、泛化总结、旧产品 / 竞品和纯服务纠纷污染进入正式聚合。本阶段不接入 active upload、worker、results、export 或 frontend。5.9.4.1-A 明确：5.9.3 继续负责证据真实性与对象边界，不负责生成最终卖家 TOP10 key，也不推翻前两阶段契约。

## 模块

新增实验模块：

- `backend_api/app/services/review_fragment_evidence_gate.py`
- 测试 fixture：`backend_api/tests/fixtures/review_fragment_evidence_5_9_3_samples.json`
- 单元测试：`backend_api/tests/test_review_fragment_evidence_gate.py`

版本：

- `review-fragment-evidence-gate.5.9.3`
- `review-fragment-evidence-gate-samples.5.9.3`

该模块只提供纯函数，不被上传、worker、结果页、导出或前端引用。

## 输入

每个片段仍沿用 5.9.1 的 9 个基础字段：

`fragment_text`、`module`、`aspect_key`、`polarity`、`evidence_span`、`confidence`、`current_product_scope`、`can_aggregate`、`reject_reason`

review 级输入需要额外提供原始 `review_text`，并传入 5.9.2 解析出的当前 `sub_category` taxonomy whitelist。

## 三层标签边界

证据 gate 只在基础 fragment 上补充证据结果：

- `module` 仍是业务路由，证据 gate 用它判断当前产品、配件、履约、旧产品和审计边界。
- `aspect_key` 仍是 taxonomy 证据维度，证据 gate 检查证据是否真的支持该维度；它不是卖家展示标签。
- `issue_key` / `highlight_key` 只在下游 artifact 层出现，用于卖家可行动问题 / 亮点 TOP10。证据 gate 不把它们加入 5.9.1 基础字段，也不因缺少它们而改写原文证据。

正式 TOP10 的业务定义是“卖家可行动问题 / 亮点 TOP10”。因此，证据 gate 的 `can_aggregate=true` 只表示片段可以继续进入后续 taxonomy / artifact 判断，不等于已经生成 approved TOP10，也不等于可以直接展示。内部 key 统一使用英文稳定 key，中文和前台英文由 display label mapping 提供。

## 输出

门禁为每个片段补充 / 修正：

| 字段 | 含义 |
|---|---|
| `evidence_valid` | `evidence_span` 是否是可追溯的原文证据。空、原文找不到、泛泛总结硬拆具体标签时为 `false`。 |
| `evidence_source` | `fragment_text`、`review_text`、`empty`、`not_found`。优先命中 `fragment_text`，否则允许命中原始 `review_text`。 |
| `can_aggregate` | 是否允许继续进入正式 artifact 的聚合判断。candidate / other 即使 evidence 有效也保持 `false`；通过本 gate 不代表已具备最终 TOP10 展示资格。 |
| `reject_reason` | 拦截原因，例如 `evidence_missing`、`evidence_not_found`、`evidence_too_generic`、`other_product_or_competitor`、`logistics_or_service`、`accessory_only`、`candidate_pending_review`。 |

测试辅助输出还包含 `taxonomy_status`，用于确认 evidence gate 与 5.9.2 whitelist 的组合结果。

## 门禁规则

1. `evidence_span` 为空：`evidence_valid=false`，`reject_reason=evidence_missing`。
2. `evidence_span` 既不在 `fragment_text`，也不在原始 `review_text`：`evidence_valid=false`，`reject_reason=evidence_not_found`。
3. `Great product`、`Nice product`、`Overall good` 等泛泛好评，不能硬拆成 `waterproof`、`comfort`、`durability` 等具体亮点：`reject_reason=evidence_too_generic`。
4. 旧产品、竞品、历史产品证据只进入对比 / 审计，不进入当前产品问题或亮点：`reject_reason=other_product_or_competitor`。
5. 纯客服、退款、退货和服务纠纷不能当成当前产品问题 / 亮点：`reject_reason=logistics_or_service`。但 `late_shipping`、`shipping_damage`、`confusing_size_chart`、`detail_page_misleading` 等有明确卖家行动对象的反馈，不应仅因属于履约或产品信息就一律判成 audit；应保留原文证据，交给后续 approved `issue_key` / `highlight_key` artifact mapping。
6. 配件证据可以继续聚合，但必须使用配件 aspect，例如 `accessory_storage`；不能把 `phone case leaked` 贴成当前 waders 的 `waterproof` 问题。错误对象归因仍拦截，正确配件证据不再因“配件”身份自动丢失。
7. 包装、物流问题可以继续聚合，但必须使用 `packaging` / `logistics_issue` 等对应 aspect；具体卖家展示 key 由后续 artifact mapping 决定，例如 `issue_key=late_shipping` 或 `issue_key=shipping_damage`。
8. `candidate:*` / `other` 必须保留 evidence，但不进入正式 TOP10。
9. `water_leaks_through`、`accessory_leak`、`late_shipping` 等卖家可读 key 不是 taxonomy aspect；证据 gate 只验证它们未来映射所依赖的原文和 `aspect_key`，不把卖家 key 直接当作 taxonomy key。

本阶段不修改 5.9.4 artifact 的 promotion 逻辑。5.9.3 的 focused negative fixture 只使用纯客服/退款污染来证明服务边界；配件、包装和后续卖家可行动问题的正式 label promotion 留给 5.9.4.1-B。

## 10 条 fixture 覆盖

| # | 样例 | 检查点 | 结果 |
|---:|---|---|---|
| 1 | `current-product-evidence-allowed` | 当前产品接缝漏水证据存在 | `seam_integrity` 可聚合。 |
| 2 | `rewritten-evidence-not-found-blocked` | evidence 是 LLM 改写 / 原文不存在 | `evidence_not_found`。 |
| 3 | `empty-evidence-blocked` | 空 evidence | `evidence_missing`。 |
| 4 | `generic-praise-hard-split-blocked` | `Great product` 被拆成多个具体亮点 | `evidence_too_generic`。 |
| 5 | `old-product-and-current-product-separated` | 旧 Brand X waders 漏水 + 当前产品 dry | 旧产品拦截，当前产品防水亮点可聚合。 |
| 6 | `logistics-service-pollution-blocked` | 纯 customer service / refund 污染 | 不算当前产品问题或亮点；可行动的 `late_shipping` 不由本阶段 fixture 定义。 |
| 7 | `accessory-evidence-object-boundary` | phone case 漏水 | `accessory_storage` 可聚合；不得变成 waders `waterproof` 问题。 |
| 8 | `packaging-arrival-damage-correct-aspects` | box damaged / repair patch missing | `logistics_issue`、`accessory_storage` 可聚合。 |
| 9 | `candidate-and-other-retain-evidence` | candidate / other 证据保留 | evidence 有效，但不进正式 TOP10。 |
| 10 | `review-text-source-evidence-allowed` | evidence 只在原始 review_text 中 | `evidence_source=review_text`，可继续聚合。 |

## 验收结论

5.9.3 已具备最小可验收能力：任何进入后续正式 artifact 的片段必须能追溯到原文证据；无证据、泛化总结、旧产品 / 竞品、纯客服售后和配件错贴主产品的问题会 fail closed；正确的配件、包装 / 到货证据可继续进入后续治理；candidate / other 仍保留 evidence，等待下游 artifact 治理。`issue_key` / `highlight_key` 和 display label mapping 不在本阶段实现。

本阶段仍不接入 active upload、worker、results、export 或 frontend，也不改变 5.9.0 waders 隔离决策点。
