# 5.9.4 candidate / other + 多模块承接 + 5.9.4.1-B

日期：2026-08-05

目标：在 5.9.1 输出契约、5.9.2 taxonomy 白名单和 5.9.3 原文证据门禁之后，用独立 artifact 处理 candidate / other、多模块承接和卖家可行动问题 / 亮点 TOP10。该实验不接入 active upload、worker、results、export 或 frontend，也不改变 5.9.0 waders 隔离决策点。

## 模块

### 最新正式模块口径

`module` 是业务归属，不是具体标签。正式输出只使用以下六个模块：

| module | 业务含义 |
|---|---|
| `product_issue` | 用户体验模块的产品问题；包含配件、包装、发货和负向客服体验等卖家可行动问题 |
| `product_highlight` | 用户体验模块的产品亮点；包含正向客服服务认可 |
| `consumer_profile` | 消费者画像；使用场景统一承接到这里 |
| `purchase_motive` | 购买动机 |
| `unmet_need` | 未满足需求 |
| `audit_filter` | 其他无法划分到上述模块的内容，例如旧产品、竞品、无证据和无法判断的片段 |

`customer_service` 不再是独立 module：

- 客服服务好 → `product_highlight`
- 客服服务差 → `product_issue`

`accessory_or_bundle`、`logistics_support`、`comparison_or_other_product`、`other_candidate` 仅作为 5.9.1-5.9.3 历史输入路由的兼容值；5.9.4.1-B 的 artifact 输出会把它们归一到上述六个正式模块。

## 三层标签边界

| 层 | 字段 | 责任 |
|---|---|---|
| 1 | `module` | 片段最终进入六个正式业务模块中的哪一个。 |
| 2 | `aspect_key` | 当前 `sub_category` 的 taxonomy 证据维度，例如 `seam_integrity`、`accessory_storage`、`size_fit`、`shipping_damage`。 |
| 3 | `issue_key` / `action_label_key` | artifact 层的卖家可读正式 key。负向问题使用 `issue_key`，亮点或默认 taxonomy 行使用 `action_label_key`。 |

本次只调整 module 口径，不提前确认 `aspect_key` 和 `issue_key` 是否最终合并。当前实验仍按现有 artifact 方案处理：`water_leaks_through` 作为卖家问题 key，由后续映射归一。

所有路由和聚合只使用英文稳定 key。`display_label_en`、`display_label_zh` 只由实验模块内的 display label mapping 生成，不参与匹配、去重或计数。

## 正式 TOP10 口径

正式 TOP10 是“卖家可行动问题 / 亮点 TOP10”，不等同于狭义产品本体质量 taxonomy，也不等同于所有 `can_aggregate=true` 的片段列表。

进入 `formal_top10_rows` 必须同时满足：

1. `evidence_span` 能追溯到片段或原始评论。
2. 旧产品、竞品和无证据片段仍被 gate 拦截；客服正负向不再使用独立 module，而是按极性进入产品问题或产品亮点。
3. 片段的证据维度能解析到当前 `sub_category` 的 taxonomy，或已经有 approved seller-action mapping。
4. 行的最终聚合 key 是 `issue_key` 或 `action_label_key`，而不是把它写进 `aspect_key`。

approved mapping 可以把证据有效的 candidate / other 或旧路由片段提升为正式行，但不会绕过 taxonomy 证据维度校验。candidate / audit 不得继续输出以下已批准正式问题：

- `water_leaks_through`
- `accessory_leak`
- `missing_accessory`
- `confusing_size_chart`
- `late_shipping`
- `customer_service_unresponsive`

## Approved seller-action mapping

| 正式 key | 类型 | taxonomy `aspect_key` | artifact module | 展示文本 |
|---|---|---|---|---|
| `water_leaks_through` | issue | `seam_integrity` / `waterproof` | `product_issue` | `Water Leaks Through` / `容易进水` |
| `accessory_leak` | issue | `accessory_storage` | `product_issue` | `Accessory Leaks` / `配件漏水` |
| `missing_accessory` | issue | `accessory_storage` | `product_issue` | `Missing Accessory` / `缺少配件` |
| `confusing_size_chart` | issue | `size_fit` | `product_issue` | `Confusing Size Chart` / `尺码表不清` |
| `late_shipping` | issue | `shipping_damage` | `product_issue` | `Late Shipping` / `发货晚` |
| `customer_service_unresponsive` | issue | `customer_service` | `product_issue` | `Customer Service Unresponsive` / `客服响应不及时` |
| `customer_service_helpful` | highlight | `customer_service` | `product_highlight` | `Helpful Customer Service` / `客服服务好` |

普通 taxonomy 亮点保留 taxonomy aspect，并以 `action_label_key` 作为 artifact 稳定 key。例如 `aspect_key=waterproof` 的正向片段输出 `action_label_key=waterproof`。

## Artifact 输出

### `formal_top10_rows`

正式行至少包含：

| 字段 | 含义 |
|---|---|
| `module` | approved mapping 归一后的业务模块。 |
| `aspect_key` | 原文证据对应的 taxonomy 维度；漏水合并行另保留 `aspect_keys` 集合。 |
| `issue_key` | approved 负向卖家问题 key；亮点行为空。 |
| `action_label_key` | 亮点或未单独治理的正式 taxonomy 行 key；问题行为空。 |
| `display_label_en` / `display_label_zh` | 由 mapping 生成的展示文本。 |
| `normalized_label` | 最终卖家稳定 key，用于本 artifact 聚合。 |
| `evidence_span` | 代表证据。 |
| `count` | 按最终 `issue_key` / `action_label_key`、模块、子品类和极性聚合后的次数。 |
| `representative_comments` | 最多 3 条代表原评论。 |

漏水的两条样本分别命中 `seam_integrity` 和 `waterproof`，但使用同一个 `issue_key=water_leaks_through`，因此只生成一条正式问题行，`count=2`。

### `module_seed_rows`

消费者画像、使用场景、购买动机仍走模块级 seed taxonomy，不进入正式产品 TOP10。使用场景统一承接到 `consumer_profile`。

### `candidate_rows`

保留证据但不正式聚合的未满足需求、未覆盖 seed 和其他候选。`can_aggregate=false`，`issue_key` / `action_label_key` 为空。已批准的五个正式问题不得出现在这里。

### `audit_rows`

保留旧产品 / 竞品、无证据和无法划分到六个正式模块的污染片段。客服正负向如果证据明确，应分别提升为 `product_issue` 或 `product_highlight`；`late_shipping` 等有明确卖家行动对象的反馈也不应落到这里。

## Fixture 覆盖

`review_fragment_candidate_5_9_4_samples.json` 共 10 条样本，覆盖：

- 人群、使用场景进入消费者画像。
- 购买原因进入购买动机。
- 期待缺口进入 `unmet_need` candidate-first。
- 漏水两种 taxonomy aspect 统一聚合为 `water_leaks_through`。
- 配件漏水、配件缺失、尺码表不清、发货晚进入正式问题行。
- 正向 `waterproof` 亮点使用 `action_label_key`。
- 客服负向进入 `product_issue`，客服正向进入 `product_highlight`。
- candidate / audit 不残留已批准正式问题 key。

## 隔离边界

本实验只被 focused pytest 引用，不修改上传、worker、结果页、导出、frontend 或 waders 旧规则入口。
