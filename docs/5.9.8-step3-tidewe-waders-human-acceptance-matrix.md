## 2. 术语口径

- `应进明细`：该 Customer Issue / Customer Label 可在单条评论明细中展示。
- `应进 Top source-review`：该 occurrence 可进入 Top10 聚合的 source-review occurrence 候选；是否最终进入 Top10 取决于真实上传后的全量计数。
- `evidence_verified`：期望为 `true`，且 evidence span 必须能在同一条评论原文中定位。
- `cluster_propagated`：单条明细和 Top source-review 期望一律为 `false`。
- `context/low-priority`：如 `not_used_yet`、`first_impression_positive`、`overall_dissatisfied`，可用于单条明细或审计，但默认不强制进入 Top10 主榜。
- `candidate`：Step 1 已提出但当前 catalog/allow-list 尚未完全落地的细粒度标签，验收时记录为命名/归类待确认，不应误判为四件套或 broad label。

## 5. 重点验收门禁

- 单条明细无 evidence 展示率 = `0`。
- 单条明细 cluster propagated 展示率 = `0`。
- Customer Label 四件套不得在无 evidence / 未使用 / 泛泛好评 / 负面评论中批量出现。
- `water_leaks_through` 不得由 no leaks、leak proof、旧产品/他牌、phone case/pocket 触发。
- phone case / pocket 漏水只能归 `accessory_storage`，优先 `pocket_not_waterproof` 或 accessories issue。
- 同一 label 在结果页 Top10、单条评论明细、raw review XLSX、后端完整导出、单标签下载中的 evidence/cluster 口径必须一致。
