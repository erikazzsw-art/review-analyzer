# 需求记录：标签数据层回归英文 canonical key

> 日期：2026-06-25
> 需求来源：Erika 提出"原文下载按钮不工作" → 深入讨论后发现根因是标签架构偏离设计

## 需求描述

将分析结果中的 `issue_tag` / `highlight_tag` 存储从中文标签（如"耐用性"）回归为英文 canonical label（如"Durability"），使其与竞品调研确定的三层架构一致：

```
L2 数据层: 英文 canonical key → DB 存储 & LLM 输出
L1 展示层: i18n 字典翻译 → 按用户语言显示
L0 业务层: 11 类中文大类 → 派生自 L1
```

同时修复因 insight_engine AI 重命名 tag 导致前端下载按钮无法匹配评论原文的问题。

## 问题根因

1. `category_grouper.py` 调用 `aspect_to_zh()` 把 taxonomy key 转为中文存入 DB（违反 L2 英文原则）
2. `insight_engine.py` 的二次 AI 调用把中文 tag 改写为不一致的英文（如"稳固性"→"Sturdiness"）
3. 前端拿到被改名的 tag → 无法匹配评论字段中的值 → 下载按钮失效

## 解决方案

| 文件 | 改动 |
|------|------|
| `backend_api/app/services/category_grouper.py` | 新增 `aspect_to_en()`；`_aspects_to_issue_tag` / `_aspects_to_highlight_tag` 改用英文标签 |
| `review_analyzer/insight_engine.py` | AI merge 逻辑跳过 tag 数组覆盖，只增强 summary 文本；删除 `_inject_original_tags` |
| `frontend/src/components/analysis/analysis-results-sections.tsx` | 下载匹配简化为精确匹配；按钮文案及导出列名改英文 |

## 工作量评估

- **规模**：S（3 文件，净减 38 行代码）
- **涉及岗位**：后端开发 0.5h + 前端开发 0.5h
- **风险**：低（不改 DB schema、不改 prompt、不改 API 接口）
